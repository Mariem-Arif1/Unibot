## Summary

Implement durable chat session and message persistence for Aivora. Each authenticated user can
create multiple named sessions per bot; every message is stored and correctly associated with its
(user, bot, session) triple. The feature exposes a versioned REST API for session CRUD and
paginated message history. Session isolation is enforced at the SQL query layer (always filter by
user_id + session_id). An audit log table records session create/delete events. This feature is
consumed by F4 (LLM streaming — stores completed assistant messages) and F7 (Web UI — session
sidebar, message history).

---

## Technical Context

**Language/Version**: Python 3.13 (backend)

**Primary Dependencies**:
- FastAPI 0.115.5
- SQLAlchemy 2.x (async, mssql+aioodbc)
- Alembic (migrations)
- pydantic 2.10.3
- PyJWT (via F1 auth dependency — `get_current_user` from `src/dependencies.py`)
- passlib[bcrypt] + bcrypt==3.2.2 (pinned — already in requirements.txt)

**Storage**: SQL Server (`mssql+aioodbc://sa:sa@localhost/agents?driver=ODBC+Driver+17+for+SQL+Server`)
- UUID → `String(36)`
- Role enum → `String(20)` + `CHECK` constraint
- Timestamps → `DateTime`, server default `GETUTCDATE()`
- Message content → `Text` (maps to `NVARCHAR(MAX)`)

**Testing**: pytest + httpx (async integration tests against real SQL Server DB)

**Target Platform**: Self-hosted server (same as F1)

**Project Type**: Web application — FastAPI backend (frontend handled by F7)

**Performance Goals**: Session list < 500 ms · Paginated history (50 msgs) < 300 ms

**Constraints**:
- Session isolation enforced at DB query level (user_id + session_id on every query)
- `bot_id` stored without FK constraint until F2 creates the `bots` table
- No soft-delete; deletion is permanent with CASCADE to messages
- Page size server-enforced max: 200

**Scale/Scope**: ~50–200 users, up to 10,000 messages per session
