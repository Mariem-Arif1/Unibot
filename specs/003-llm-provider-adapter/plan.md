## Summary

Implement the LLM provider adapter layer for Aivora. A new `POST /sessions/{session_id}/chat`
endpoint accepts a user message, persists it (via F3), assembles the conversation history with
the bot's system prompt (truncating to the context window), calls the configured LLM provider
(Anthropic or OpenAI), and streams the response token by token to the client via SSE. On stream
completion, the assembled assistant message is persisted (via F3). Each bot has its own provider,
model, system prompt, and generation parameters stored in the DB. Provider implementations are
hidden behind a `LLMProvider` protocol so new providers require only a new adapter file.

## Technical Context

**Language/Version**: Python 3.13 (backend)

**Primary Dependencies**:
- FastAPI 0.115.5 (StreamingResponse for SSE)
- SQLAlchemy 2.x async (mssql+aioodbc)
- pydantic 2.10.3
- `anthropic>=0.25.0` (Anthropic Python SDK)
- `openai>=1.30.0` (OpenAI Python SDK)
- Existing F1/F3 services (`get_current_user`, `MessageService`, `SessionService`)

**Storage**: SQL Server — new `bots` table; FK from `chat_sessions.bot_id → bots.id`

**Testing**: pytest + httpx + `pytest-asyncio`; provider calls mocked with `unittest.mock.AsyncMock`

**Target Platform**: Self-hosted server (same as F1, F3)

**Project Type**: Web application — FastAPI backend extension

**Performance Goals**: First SSE token < 3 s · Full response (2000 tokens) delivered without drops

**Constraints**:
- Provider API keys from env vars only — never in DB or logs
- System prompt NEVER truncated; only conversation history is truncated
- No partial assistant message persisted on error
- Single in-flight LLM call per session (asyncio.Lock, HTTP 409 on contention)
- SSE error event sent if provider error occurs after streaming has started

**Scale/Scope**: ~50–200 concurrent users; one LLM call per active chat
