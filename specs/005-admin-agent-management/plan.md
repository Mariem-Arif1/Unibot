# Implementation Plan: Admin Agent Management

**Branch**: `005-admin-agent-management` | **Date**: 2026-06-11 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/005-admin-agent-management/spec.md`

## Summary

Add an admin-only interface for creating, editing, deactivating, and deleting AI agents (bots). The backend extends the existing bot schemas and registers a new admin CRUD router protected by the `require_role(UserRole.admin)` dependency that already exists in `dependencies.py`. The frontend adds an `/admin` layout with a role-checked middleware gate, an agent list table, and a shared create/edit form covering all bot fields.

## Technical Context

**Language/Version**: Python 3.11+ (backend), TypeScript / Next.js 14 App Router (frontend)

**Primary Dependencies**:
- Backend: FastAPI, SQLAlchemy async, Pydantic v2, `aioodbc` (SQL Server)
- Frontend: Next.js 14, TailwindCSS, SWR, Radix UI, Lucide icons, `jwt-decode`

**Storage**: SQL Server via `mssql+aioodbc` — no migrations required (all Bot columns already exist)

**Testing**: pytest (backend), existing test conventions (frontend)

**Target Platform**: Web browser (desktop-first) + FastAPI server on Windows / Docker

**Project Type**: Web application (FastAPI backend + Next.js frontend)

**Performance Goals**: Admin list loads ≤ 2 s; form submit round-trip ≤ 1 s under normal conditions

**Constraints**: No DB migrations. `require_role` already exists and must be reused — do not create a second admin-check mechanism.

**Scale/Scope**: < 100 agents total; no pagination required for v1.

## Phase 0: Research

*See [research.md](research.md) for full findings. Key decisions summarised here.*

### Key Design Decisions

**Decision 1 — Reuse `require_role`**
`dependencies.py` already exports `require_role(*roles: UserRole)`. Admin endpoints use `Depends(require_role(UserRole.admin))` directly — no new dependency created.

**Decision 2 — Separate admin router (`admin_bots.py`)**
A dedicated `admin_bots.py` router with prefix `/admin/bots` keeps admin CRUD isolated from the user-facing `bots.py`. This prevents any accidental exposure of create/update/delete on the public `/bots` route.

**Decision 3 — Role check in Next.js middleware**
The middleware already decodes the JWT. Extending it to read `payload.role` and redirect `/admin/*` to `/bots` for non-admins adds zero new dependencies and keeps the gate server-side (Edge Runtime). The admin layout adds a secondary client-side guard.

**Decision 4 — `BotAdmin` type in frontend**
The existing `Bot` interface omits sensitive fields (`system_prompt`, `temperature`, `max_tokens`, `context_window_tokens`) intentionally (T032 compliance). A new `BotAdmin` interface exposes all fields and is used only in admin-scoped components and services.

**Decision 5 — Shared `AgentForm` component**
Create and edit pages both render the same `AgentForm` component. The form receives an optional `initialValues` prop: when present it pre-fills for edit; when absent it uses defaults for create. On submit it calls the appropriate service function.

**Decision 6 — `agent_type` as a select with a fixed options constant**
The dropdown is driven by a `AGENT_TYPE_OPTIONS` constant in the form component, making new types addable without touching form logic. V1 options: `""` (Generic Assistant) and `"promo_discount"` (Promo & Discounts).

## Phase 1: Design Artifacts

*See [data-model.md](data-model.md), [contracts/api.md](contracts/api.md), and [quickstart.md](quickstart.md).*

### Backend Implementation Plan

#### Step 1 — Extend `backend/src/schemas/bot.py`

Add three new schemas alongside the existing `BotOut` and `BotListOut`:

- `BotCreate` — all fields, required: name, provider, model; defaults for the rest
- `BotUpdate` — all fields optional (partial update / PATCH semantics via PUT)
- `BotAdminOut` — full field set including system_prompt, temperature, max_tokens, context_window_tokens, created_at

#### Step 2 — Create `backend/src/api/v1/admin_bots.py`

Four endpoints, all behind `Depends(require_role(UserRole.admin))`:

| Method | Path | Description | Response |
|--------|------|-------------|----------|
| GET | `/api/v1/admin/bots` | List all bots (incl. inactive) | `BotAdminOut[]` 200 |
| POST | `/api/v1/admin/bots` | Create bot from `BotCreate` | `BotAdminOut` 201 |
| PUT | `/api/v1/admin/bots/{bot_id}` | Partial update from `BotUpdate` | `BotAdminOut` 200 |
| DELETE | `/api/v1/admin/bots/{bot_id}` | Hard delete | `204 No Content` |

Deactivation is achieved via PUT with `is_active: false`. DELETE is a permanent hard delete.

#### Step 3 — Register in `backend/src/api/v1/router.py`

Add `admin_bots` import and include the router under prefix `/admin/bots` with tag `"admin"`.

### Frontend Implementation Plan

#### Step 4 — Extend `frontend/src/middleware.ts`

Change `jwtDecode<{ exp: number }>` to `jwtDecode<{ exp: number; role: string }>`. Add role guard for `/admin` prefix before the expiry check falls through.

#### Step 5 — Add `BotAdmin` to `frontend/src/types/index.ts`

New interface with all bot fields including system_prompt, temperature, max_tokens, context_window_tokens, created_at.

#### Step 6 — Create `frontend/src/services/adminBotService.ts`

Four functions using existing `apiClient`:
- `listAllBots(): Promise<BotAdmin[]>`
- `createBot(data: BotCreate): Promise<BotAdmin>`
- `updateBot(id: string, data: Partial<BotCreate>): Promise<BotAdmin>`
- `deleteBot(id: string): Promise<void>`

#### Step 7 — Create `frontend/src/hooks/useAdminBots.ts`

SWR hook: `useAdminBots()` → `{ bots, isLoading, error, mutate }`.

#### Step 8 — Create admin UI components

**`AgentTable.tsx`** — Tailwind `<table>`. Columns: Name, Provider, Model, Agent Type badge, Status pill (Active/Inactive), Actions (Edit → navigate; Activate/Deactivate → PUT; Delete → open dialog).

**`AgentForm.tsx`** — Controlled form fields:
- Name: `<input type="text">` required
- Description: `<textarea>` optional
- Provider: `<select>` options Anthropic / OpenAI
- Model: `<input type="text">` required (e.g. "claude-sonnet-4-6")
- System Prompt: `<textarea>` required, tall (8 rows)
- Temperature: `<input type="range" min="0" max="1" step="0.1">` + numeric readout
- Max Tokens: `<input type="number">`
- Context Window Tokens: `<input type="number">`
- Agent Type: `<select>` driven by `AGENT_TYPE_OPTIONS` constant
- Is Active: `<input type="checkbox">` / toggle

Receives `initialValues?: BotAdmin`, `onSubmit(data)`, `isSubmitting`, `submitLabel`.

**`DeleteAgentDialog.tsx`** — Radix UI `<Dialog>`. Shows agent name. Cancel + Delete (red) buttons. Calls `onConfirm()` or `onCancel()`.

#### Step 9 — Create admin pages

- `admin/layout.tsx` — `"use client"`. On mount: decode `aivora_access` cookie, if `role !== "admin"` call `router.replace("/bots")`. Renders `<AppHeader>` + children.
- `admin/agents/page.tsx` — `useAdminBots()` + `<AgentTable>`. "Create Agent" button navigates to `/admin/agents/new`.
- `admin/agents/new/page.tsx` — `<AgentForm>` with no initialValues; on submit calls `createBot()` then navigates to `/admin/agents`.
- `admin/agents/[id]/edit/page.tsx` — SWR fetches single agent via `GET /api/v1/admin/bots/{id}`; renders `<AgentForm initialValues={bot}>`.

#### Step 10 — Admin nav link in `AppHeader.tsx`

On mount decode JWT cookie. Conditionally render an "Admin" `<Link href="/admin/agents">` when role is `"admin"`.
