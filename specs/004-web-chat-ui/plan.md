## Summary

Implement the Aivora web application using Next.js 14 App Router. The app authenticates users via
httpOnly cookies (F1), displays their assigned bots (F4), lets them create and switch chat sessions
(F3), and streams LLM responses token by token (F4 SSE). The layout is responsive — three-panel
on desktop (bot list | session sidebar | chat area), drawer-based on mobile. Key UX details:
optimistic message display, typing indicator during stream, input disabled while streaming, silent
token refresh, and inline error states. No new backend tables — the frontend consumes F1/F3/F4
REST APIs and SSE endpoints.

## Technical Context

**Language/Version**: TypeScript 5.x · Node.js 20+ (build tooling)

**Primary Dependencies**:
- Next.js 14 (App Router)
- React 18
- Tailwind CSS (styling)
- shadcn/ui + Radix UI (accessible components)
- `swr` (data fetching + caching for bot/session lists)
- `@microsoft/fetch-event-source` (POST SSE for streaming)
- `react-markdown` + `remark-gfm` (Markdown rendering in assistant messages)
- `vaul` (mobile drawer/sheet)

**Storage**: None (frontend only — all data via backend REST/SSE)

**Testing**: Jest + React Testing Library (component tests) · Playwright (E2E, optional for v1)

**Target Platform**: Modern browsers — latest 2 versions of Chrome, Firefox, Edge, Safari

**Project Type**: Web application — Next.js frontend consuming FastAPI backend

**Performance Goals**: Login→first chat interaction < 60 s · Page transitions < 500 ms · First SSE token visible < 3 s

**Constraints**:
- httpOnly cookies managed by browser — frontend never reads JWT directly
- `credentials: "include"` on all API fetch calls
- 401 interceptor: call `/auth/refresh` once, retry original request, redirect to `/login` on second 401
- Input disabled during active stream (no concurrent messages)
- Responsive: 375px mobile through 1920px desktop

**Scale/Scope**: ~50–200 users, ~4 pages, ~15 components
